1
Learn the language Month 1
Python Crash Course · Exercism · pythontutor · 2 hrs/day
▶
What to learn — in this order, no skipping
Variables, types, print, input — write 5 programs that actually do something for you personally
Conditions + loops — build a number guessing game, a times-table printer, a basic calculator. Stay here until loops feel automatic
Functions — rewrite everything you built above using functions. This is where coding starts clicking
Lists and dictionaries — spend extra time here, do 15+ exercises. This is Python's soul and the foundation of all data work
Strings — slice, split, join, format. You'll use these every single day in research code
File I/O + error handling — read/write files, try/except. Non-optional in any real project
Where to practice
Book: Python Crash Course — Eric Matthes (Part 1, Ch 1–11)
Read a chapter. Close the book. Write the examples from memory. Do every exercise at the end. This is your daily anchor.

Problems: Exercism.io → Python track
Free. Do 2 problems per day. Each one is small, auto-graded, and teaches one concept. Best beginner practice site that exists.

Debug: pythontutor.com
Paste any confusing code and watch it run step-by-step. Use this whenever something breaks and you don't know why.

Environment: VS Code + Python extension only
Plain .py files, run in terminal. No Jupyter yet — that comes later. Clean and fast.
Month 1 project
Build a word frequency counter: read any .txt file, count how often each word appears, print the top 20. Uses everything — file I/O, dictionaries, sorting, functions. If you can build this without help, Month 1 is done.
2
Build problem-solving instincts Month 2
Intermediate Python · LeetCode Easy · first real project · 3 hrs/day
▶
What to learn
Classes and OOP — write a 3D Point class, a BoundingBox, a Camera. Graphics and ML code is entirely object-oriented
List comprehensions + lambda — [x*2 for x in data]. Cleaner and faster. All ML code uses these constantly
Modules — import your own code across files, understand how packages work. Every research repo is structured this way
NumPy — all of it. Arrays, slicing, broadcasting, vectorized ops. Spend 10 solid days here. This replaces for-loops in all scientific code
Matplotlib basics — plot arrays, display images, visualize results. You'll use this to inspect every output you produce in the lab
Where to practice
NumPy: "100 NumPy Exercises" — free on GitHub
Search: "100 numpy exercises rougier github". Do all 100 in order. Single best resource for making NumPy second nature.

Problems: LeetCode — Easy, arrays and strings only
1 problem per day. Don't grind it — just keep your raw Python instincts sharp while you learn NumPy. Filter by tag: Array, String, Hash Table. These three tags cover 80% of what you'll need as an ML engineer.

Book: Python for Data Analysis — Wes McKinney
Ch 4 (NumPy) and Ch 5 (Pandas) only. Written by the creator of Pandas. Most precise explanation of how NumPy actually works.
Month 2 project
Load an image with NumPy (no OpenCV), apply a Gaussian blur manually using convolution, display before/after with Matplotlib. You've done DIP practicals — this is the same math, now you write it yourself in Python from scratch.
LeetCode note: you are NOT preparing for FAANG interviews. You're using it as a gym. Easy problems only, 1/day, until it becomes mechanical. The moment a problem feels hard, skip it and come back in a week.
3
PyTorch + Prof. Lee's slides together Month 3
Deep learning tools · research code · 4 hrs/day split
▶
Run both tracks every day
Morning · 2 hrs — PyTorchLearn the building blocks: tensors, autograd, nn.Module, training loop, data loading. Write everything from scratch — no copying.
Afternoon · 2 hrs — Prof. Lee's slidesEvery concept you don't understand, you write a small Python file that tests it. Frequency decomposition → FFT in NumPy. Video frames → load as tensors, manipulate them.
PyTorch — exact learning order
Tensors — same as NumPy but GPU-ready. Reshape, slice, move between CPU and GPU
Autograd — how gradients flow backward. Understand this deeply. It is the entire engine of deep learning
nn.Module — build a small network by hand: linear layers, activations, forward pass. No pretrained models yet
Training loop — loss, .backward(), optimizer.step(). Write this from scratch at least 5 times until it's muscle memory
Dataset + DataLoader — every real project starts here. Learn to load your own data cleanly
Where to practice
PyTorch: official "Learn the Basics" — pytorch.org/tutorials
7 short tutorials. Do one per day for week 1. Then redo all 7 without looking at the code. Muscle memory matters here.

fast.ai Practical Deep Learning — free at course.fast.ai
Lesson 1 only to start. Top-down approach — you run real models first, then understand internals. Extremely motivating. Jeremy Howard is the best ML teacher on the internet.

Papers with Code — paperswithcode.com
Start reading the implementation of 1 paper per week. You don't need to understand everything — just read real research code and notice patterns. This is what separates ML engineers from tutorial followers.

Your own PhysiGS code
Re-read it. You already implemented Cook-Torrance BRDF, COLMAP processing, Gaussian splatting training. That is real PyTorch. You know more than you think.
Month 3 project
Train a small CNN on CIFAR-10 from scratch — no tutorials, just the PyTorch docs. Write the dataset loader, the model, the training loop, the evaluation. Plot loss curves with Matplotlib. This is the standard "can you actually do ML" proof of work.
4
During your masters — career-level Python Ongoing
What to keep doing once you arrive in Taiwan · 1 hr/day alongside coursework
▶
Practice — keep this running the entire masters
LeetCode: move to Medium — 1 problem/day
Tags: Array, Hash Table, Two Pointers, Sliding Window, Dynamic Programming (basic). ML engineers at top companies get asked these. Not urgent now — but by end of Year 1 in masters, you want 150+ Mediums solved.

Kaggle — kaggle.com
Join 1 competition per month. Even finishing last teaches you more than any tutorial. The notebook ecosystem shows you how real practitioners write ML code. Start with "Getting Started" competitions.

Papers With Code — weekly habit
Pick 1 paper from your lab's area. Find its official code. Read the training script. You don't implement — just read. Pattern recognition accumulates fast.

GitHub — build a public portfolio
Every project you build goes here with a clean README. By end of Year 1: word counter, image blur, CNN trainer, 1 Kaggle notebook, 1 reproduction of a paper experiment. This is your ML engineer resume.
Books — read these slowly during masters, one chapter per week
Fluent Python — Luciano Ramalho
Advanced Python internals — decorators, generators, metaclasses, async. What separates junior from senior Python engineers. Don't touch before September.

Designing Machine Learning Systems — Chip Huyen
How ML actually works at companies — data pipelines, model serving, monitoring, deployment. Essential for ML engineer role. Read in Year 1.

Deep Learning — Goodfellow, Bengio, Courville (free PDF)
The canonical textbook. Use as reference when coursework hits a topic — not for linear reading.

Mathematics for Machine Learning — Deisenroth (free PDF)
Linear algebra, probability, calculus — the math under everything. Your DIP and linear algebra background means this will click faster than you expect.
One thing that separates ML engineers from everyone else
Read research code on GitHub — not just tutorials. The MIT Missing Semester (free, one weekend) teaches you Git, shell, and debugging tools that make you 2x faster in any codebase. Do this in your first month in Taiwan.
By end of Year 1 in masters: solid LeetCode Medium habit, 1–2 Kaggle finishes, PhysiGS + lab projects on GitHub, Chip Huyen's book read. That profile gets you interviews at ML companies. Everything before September is just building the foundation for this.
